# Macos Contextual Search

## 2026-09-06 — macOS Contextual Search tool -- architecture decisions

**Decisions:** v1 query surface is a pure terminal CLI (e.g. `csearch "..."`), not a Finder Sync extension -- avoids Xcode/code-signing/manual-extension-approval overhead for an MVP. Nothing is ever hard-deleted: dupes/unneeded files move to a dated quarantine folder with a manifest; permanent removal is a manual step Dex takes afterward. "Combo" (Dex's own definition): run both engines, automatic fallback if the primary fails, not a dual-score-every-query ensemble. Embeddings: Apple MLX primary (native to Apple Silicon, no PyTorch); on failure/exception, fall back automatically to sentence-transformers, logging which backend served each request. OCR: Apple Vision framework primary (native, no install); on failure or empty/low-confidence text, fall back automatically to Tesseract (Homebrew), logging which engine served each result. Dex also wants the tool built efficient, robust, and innovative from an engineering perspective, not just functional -- see the filled tool_blueprint and engineering notes for the concrete shape that takes (incremental FSEvents-driven indexing, cached embeddings keyed on content hash, background reindex at low OS priority, structured fallback logging, a `--doctor` health-check subcommand). Execution happens via a local Claude Code session on Dex's Mac through Terminal -- this cloud session writes the code but cannot run/install anything on his machine.
**Facts / preferences:** Baseline already has Homebrew + python3 installed on the Mac (local session should still verify exact versions as step 1, not assume). Xcode Command Line Tools required regardless of other choices. Dex explicitly wants to be consulted before any new app/package gets added -- nothing gets installed without discussing it with him first (see also tool-blueprint-workflow.md for how this planning conversation itself should conclude).

## 2026-09-06 — Scaffold built, tested, and pushed

**Decisions:** Core package is stdlib-only on purpose -- `pip install -e .` pulls zero third-party packages, so keyword search works immediately and MLX/sentence-transformers/pypdf/OCR are opt-in extras. That encodes Dex's "discuss before installing" rule in the packaging itself rather than relying on anyone remembering it. Everything expensive (hashing, extraction, embedding) is keyed on content hash rather than path, so reorganizing files -- which this tool actively encourages -- costs no re-extraction or re-embedding. Keyword (BM25) and semantic (cosine) rankings are fused by reciprocal rank fusion rather than blended scores, avoiding an invented conversion factor between incomparable scales. Brute-force exact vector scoring over float32 blobs instead of adding sqlite-vec/FAISS -- revisit only past ~1M documents. Deletion is structurally absent: `quarantine.py` was written before any dedupe logic, and a test parses its AST to assert it never calls os.remove/Path.unlink/shutil.rmtree, with a second test proving that guard can actually fail.
**Facts / preferences:** Dex gave blanket install permission mid-build and stepped out with phone remote control. Installing in the cloud container is safe and separate from his Mac -- used it to verify the semantic path for real rather than shipping it unproven. His local Claude Code session (seen in a screenshot) is NOT reachable from this cloud session: ListAgents only sees sessions on this machine, so peer messaging cannot drive his Terminal.
**Artifacts:** https://github.com/DexterBrandonJr/macos-contextual-search -- main has the scaffold (commit f8a5d0a, 34 files), draft PR #1 (claude/verify-semantic-path) has the semantic verification. 45 tests pass. Verified working end-to-end: indexing with node_modules pruning, content-hash dedupe reuse, keyword search, duplicate reporting, history, and critically the premise itself -- query "how much money went to advertising" returns 0 keyword hits but ranks the right document #1 semantically. The fallback chain was observed firing for real ("fell back to sentence-transformers after mlx (unavailable)"), which is the exact path his Mac takes if the MLX adapter needs correcting.
