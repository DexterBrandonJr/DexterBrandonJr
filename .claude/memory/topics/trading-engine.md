## 2026-09-07 — Build step 1 shipped: protected risk rules + circuit breaker, draft PR #1

**Decisions:** Two design calls made while building that weren't in the plan and are worth keeping. First, `ALL_RULES` (the registry of which rules run) lives inside the protected rules file rather than in the orchestrating gate -- otherwise dropping a rule would need no protected file touched, which defeats the guardrail entirely. A test also asserts every `rule_*` function defined is registered, so a rule can't be written, tested, and left dead. Second, domain dataclasses live in an unprotected `models.py` while policy lives in the protected file, so adding a field never rewrites the rules -- the boundary being "shapes are not policy," documented in both files. Also settled: the guardrail is two independent layers, not one. A checksum catches any change at all (and forces the regenerated manifest into the same diff, which is the actual point -- visibility to a reviewer, not cryptographic security, since whoever edits the file can also regenerate the manifest); an AST purity check separately enforces invariants that must survive a *legitimate* checksum-updated edit (no network, no I/O, no order placement in a policy file).
**Facts / preferences:** Verified the guardrails against real tampering rather than only synthetic test doubles -- widening the size cap back to 15% was caught by the checksum, adding `urllib` to the circuit breaker was caught independently by both layers. This is the direct application of the earlier lesson in this project that a green checkmark can be misleading: a guard only observed passing is indistinguishable from a guard that cannot fail, so every guard has a test that makes it fail on purpose. The one confirmed real-world failure in Dex's trade history (same ticker held across three accounts) is now reconstructed as a named test that the ticker and thesis rules both refuse.
**Artifacts:** `DexterBrandonJr/trading-engine` draft PR #1 (branch `claude/gate-rules-and-kill-switch`): `gate/rules.py`, `kill_switch.py`, `models.py`, the `tests/guardrails/` machinery with a manually-run checksum updater, and CI on Python 3.11-3.13 including a job proving the core install pulls no third-party packages. 88 tests, stdlib-only. Session is subscribed to PR activity.
**Open threads:** Build order steps 2-9 remain, next is the Webull API clients (read-only calls first -- balances, positions, quotes -- before anything can place an order). Nothing built so far touches the network or places an order.

## 2026-09-07 — Build step 2 shipped: read-only Webull clients; OTOCO confirmed in the real SDK

**Decisions:** Use Webull's official Python SDK for request signing rather than hand-rolling it. Webull signs every request with HMAC-SHA256 over a canonical string; writing that by hand would mean guessing at a format only verifiable against a live credential, where a subtly wrong signature is a 401 with nothing to debug. This is the opposite call from the csearch MLX adapter and for a good reason -- there, no alternative to guessing existed; here the vendor ships the implementation. The SDK is an *optional* extra, not a hard dependency, and exactly one module (`data/session.py`) imports it, so every other module tests with no vendor package, no credential and no network. Second decision: read-only is structural, not documented. The SDK's order object carries `list_open_orders` next to `place_order`, so the client holds it privately, forwards no attributes, and hand-writes every method.
**Facts / preferences:** Introspected the installed SDK rather than trusting doc summaries, which confirmed the two facts the whole architecture rests on: `ComboType.OTOCO` exists (the bracket order behind "works with the laptop offline and phone off") and so do `OrderTIF.GTC` and `OrderType.STOP_LOSS_LIMIT` -- the last one matters because the AG catastrophic fill was a *market* stop, and the limit variant is the fix. Also confirmed `place_order` takes a `client_order_id` (the idempotency key the plan assumed) and that `TrailingType` exists for the Stage 2 trailing-stop work. Response payloads are returned as the API shaped them: mapping them onto our models needs real field names, which take one live call to confirm, and guessing would produce a parser that looks right and silently mis-reads a balance.
**Artifacts:** `DexterBrandonJr/trading-engine` PR #2 (`claude/webull-read-only-clients`): `data/` with credentials (env-only, masked repr), a per-category sliding-window rate limiter matching Webull's documented limits, shared transport that turns a non-2xx into an exception exactly once, and the two read clients. 129 tests. Step 1 merged as `97bbec4`.
**Open threads:** Two mistakes worth remembering rather than repeating. First, I initially used Dex's *real* App Key and Secret (copied from his terminal screenshot) as test fixtures -- caught and replaced with fabricated values before any commit, but the reflex to reach for a realistic-looking constant is exactly how a credential reaches permanent git history. Second, a test that reloaded modules in-process broke two unrelated tests by swapping the exception class they had imported; the fix was a subprocess, and the blocker inside it initially used the `find_module`/`load_module` API removed in 3.12, which would have passed locally on 3.11 and silently stopped blocking in CI. ## 2026-09-08 — Build step 3: two-way sheet sync, activation guide, and a real pip resolution break

**Decisions:** Dex's call: write directly to the Master Trading Journal sheet and make it two-way, rather than the local-store-plus-CSV-export I had proposed. Authentication is a Google service account whose email he shares the sheet with -- access is one document wide, revoking it is un-sharing a file, and there is no OAuth consent screen or refresh token to maintain. The sheet is the system of record, not a copy. Four write-safety properties are structural rather than intentional: appends use INSERT_ROWS so they cannot land on an existing row; closing a trade writes eight individually-addressed cells rather than a whole row, so a column the engine does not model cannot be blanked; the Account Journal tab is never written (those rows are Dex's, and the writing methods contain no reference to that tab); and updates re-read and re-match before writing, refusing on an already-closed row or on two matching rows rather than guessing. A header check refuses to read or write at all if the columns are ever reordered.
**Facts / preferences:** A real, install-breaking dependency conflict, found by a CI job written specifically to look for it: Webull's streaming package pins `protobuf==4.21.12` while Google's API client wants a far newer one, and asking pip for both extras in one command makes it backtrack through hundreds of versions of Google's transitive dependencies before giving up with `resolution-too-deep`. It did not reproduce locally at first because the packages had been installed separately over time, so pip took the existing state as given -- reproducing it required matching CI's newer pip in a clean venv. Installing each extra in its own command works, because each resolution takes the previous as given; the pin only constrains Webull's MQTT quotes module, which this project does not use. Worth remembering as a pattern: "works on my machine" for a Python install is often an artifact of incremental installs, and a clean-venv reproduction with a current pip is the only honest test.

The activation guide is also published as an artifact for following on a phone during setup. Steps 1 and 2 merged as `97bbec4` and `8c334a6`.

## 2026-09-08 — Build step 4: free no-key context sources; CBOE chains and insider clusters are the real finds

**Decisions:** Research into better free sources changed the plan twice over, and both changes are worth keeping. First: CBOE publishes full delayed option chains free with no API key, carrying bid/ask, volume, open interest, implied volatility and all Greeks -- verified live at 3,260 contracts for one symbol. That reframes what the highest-value signal actually is for a small account. The two things that quietly destroy small options accounts are spread cost (a 0.90/1.10 quote takes a fifth of a $100 risk budget on the round trip) and paying for rich implied volatility, and neither is visible in any news feed while both are directly measurable from this one free source. Second: insider *cluster* buying is the best-documented edge on the whole source list (Lakonishok and Lee, roughly 4.8% outperformance over twelve months; Cohen/Malloy/Pomorski, about 5.2% six-month alpha on opportunistic purchases specifically), so the detector looks for several insiders acting together rather than any single filing. Deliberate honesty constraint encoded in the data: the EDGAR daily index reveals that a Form 4 was *filed*, not whether it was a buy, so these publish as `insider_cluster_candidate` with `direction: "unknown"` -- treating every cluster as bullish would invert the signal on a company whose officers are all selling.
**Facts / preferences:** Three sources need no account and no key at all -- CBOE option chains, SEC EDGAR (User-Agent required, ten requests a second), and FINRA daily short sale volume. All three verified live before any code was written against them. Conditional requests make repeat polling genuinely free: measured 2.7 MB across the three on first fetch and zero bytes on the second, all answering 304. That is the concrete answer to "little to no usage daily" -- it is a property of the fetcher, not an aspiration. FINRA publishes short *volume*, not short *interest*: short volume includes market makers hedging ordinary flow and is mostly closed out same-session, so it is a crowding measure and not a squeeze signal, and conflating the two is a common way to misread it. A live end-to-end sweep returned 78 real signals.
**Artifacts:** `DexterBrandonJr/trading-engine` PR #4 (`claude/context-sources`): `sources/` with http (conditional requests, content hashing, courtesy throttle), cboe, edgar, finra, an append-only timestamped signal store, and the sweep orchestrator, plus a scheduled `context-sweep.yml` workflow.
